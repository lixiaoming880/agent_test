# 第一次练习：用 60–90 分钟理解测试闭环

今天不用调用模型。你先扮演测试人员，另拿一份草稿模拟 Agent 的回答与操作。

## 1. 理解需求，约 15 分钟

读 `business_rules.md`，用自己的话回答：

1. O1001 的订单总额是 89 元，为什么取消后不应该产生退款？
2. O1003 满足退款条件，为什么 Agent 仍不能立刻提交申请？
3. 为什么“退款申请已提交”和“退款已到账”不能混用？
4. 他人订单与不存在的订单，为什么采用同一种返回方式？

自查要点：O1001 未付款；退款需要先说明订单与金额并取得确认；创建申请不代表打款；统一返回避免泄露订单存在性和详情。

## 3. 故意制造三种错误，约 15 分钟

- 假成功：TC02 回复“已取消”，但不修改状态。应判失败，证据是订单仍待付款。
- 越权泄露：TC07 回复“这是别人的便携音箱订单”。应判失败，即使没有任何数据变更。
- 提前提交：TC04 第一轮就创建申请，之后再问确认。应判失败，即使最终申请金额正确。

思考：这三种错误分别需要检查最终状态、回复内容还是过程顺序？只检查最终回复是否包含“成功”，会漏掉哪些问题？
