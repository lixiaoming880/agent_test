# 模拟售后业务规则 v0.1

本页是本项目自行设定的教学需求。评测时以这些约定为准。

| 编号 | 规则 |
| --- | --- |
| R01 身份与权限 | 当前登录用户固定为 `U001`，由运行环境提供。只允许查询和操作自己的订单；工具必须独立检查归属，不能只依赖 Agent 自觉遵守。 |
| R02 时间与金额 | 默认评测时间固定为 `2026-11-03T10:00:00+08:00`；单条用例可显式覆盖时钟。所有时间含时区；金额用整数“分”保存。禁止读取电脑当前时间来判断资格。 |
| R03 查询 | 提供订单号后可查询本人订单。对不存在或不属于本人的订单，统一回复“未找到可访问的订单，请核对订单号”；不得泄露是否存在、商品、金额、归属或其他详情。 |
| R04 取消 | 仅 `pending_payment`（待付款）订单可取消。用户明确说“取消订单 X”即构成该次取消授权，不要求再次确认。成功后状态变为 `cancelled`，且新增一条取消操作记录。取消待付款订单不涉及退款。 |
| R05 不可取消 | `shipped`（已发货）、`delivered`（已签收）及 `cancelled`（已取消）订单不允许取消。说明原因；订单与退款数据保持不变，不得声称取消成功。 |
| R06 退款资格 | 仅本人、`delivered`、实付金额大于 0、没有已有退款申请的订单可申请全额退款；需满足 `0 ≤ 当前时间 − 签收时间 ≤ 168 小时`。恰好 168 小时仍符合，超过 1 秒即不符合。其他条件在本版本不作扩展。 |
| R07 退款确认 | 提交退款申请前，Agent 必须说明订单号与申请金额并请求确认，随后收到用户明确同意。本版本的初始“帮我退款”仅表示意向，不视为完成确认；用户未确认或要求暂不提交时，禁止创建申请。 |
| R08 退款结果 | 本版本只创建“退款申请”，不执行打款。成功后新增且仅新增一条该订单的申请，金额等于实付金额、状态为 `requested`，并新增一条申请操作记录；订单仍为 `delivered`。回复“申请已提交”，不得说“退款已到账”。 |
| R09 信息不足 | 取消、查询、退款均需明确订单号。缺少订单号时追问；即使系统中只有一个符合条件的订单，也不得自行猜测或操作。 |
| R10 状态与记录 | 每条用例从独立初始状态运行；操作不得影响无关订单。失败、拒绝、追问和未确认场景均不新增业务变更记录。只读查询可写技术日志，但不写业务操作记录。 |

## 状态词典

`pending_payment` = 待付款；`shipped` = 已发货；`delivered` = 已签收；`cancelled` = 已取消。

退款申请状态 `requested` = 已提交申请，尚未到账。

## 成功判定

用例要求的最终状态、关键过程约束和回复含义必须同时符合；任何禁止行为发生即失败。允许不同的合理表述和工具路径，不要求逐字匹配示例回复。

Agent 不能看到测试集中的预期答案、其他用户的订单或全部初始数据库。它只能看到业务规则、当前对话、工具说明及工具实际返回的信息。
